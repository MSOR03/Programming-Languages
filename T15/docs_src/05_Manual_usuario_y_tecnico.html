5. Programar los nodos

5.1 ANDES-64 (.a64)

            .org  0x000
inicio:     LEA   R10, buf
            MOVI  R11, 0
            MOVI  R0, 3            ; destino: nodo #3
            CALL  PONER_BYTE
            MOVI  R11, 1
            MOVI  R0, 3            ; tipo PING
            CALL  PONER_BYTE
            MOVI  R2, 42
            CALL  ESCRIBIR_VALOR   ; valor en orden de red
            MOVI  R0, 6
            NSEND R0, buf          ; transmite 6 bytes
espera:     NRECV R0, buf          ; R0 = bytes recibidos
            CMPI  R0, 0
            JZ    espera
            HLT
buf:        .space 16
            .include "pdu.a64"

5.2 ORINOCO-32 (.o32)

Sintaxis en minúsculas, un token por instrucción, operandos a continuación: push 1000, pushb -1, jz etiqueta, call rutina. Etiquetas terminadas en dos puntos. Directivas .org, .word, .bytes. La ejecución empieza en la etiqueta inicio (o en 0). Recuerde que la memoria es little-endian: use bswap al leer o escribir enteros de la PDU.

5.3 CARIBE-16 (.c16)

Una instrucción por línea: LDA #5 (inmediato 0–1023), ADD var (directo), LDAX tabla (indexado por X), JSR sub / JMI sub (subrutinas; la primera palabra de sub se reserva con WORD 0). Directivas ORG, WORD, SPACE, EQU. Las expresiones admiten etiqueta+k.

5.4 Crear un escenario nuevo

def e5(verboso=False, **_):
    red = Red(ancho=300, alto=100, p_perdida=0.1, semilla=7, verboso=verboso)
    red.agregar(Nodo(1, 'ANDES-64', 'cliente_ping', 20, 50, entradas=[3, 10, 160, 200]))
    red.agregar(Nodo(2, 'CARIBE-16', 'servidor', 110, 50))
    red.agregar(Nodo(3, 'ORINOCO-32', 'servidor', 200, 50, velocidad=3, pausa=50))
    return red, 1, 20000          # red, nodo principal, límite de ticks
ESCENARIOS['e5'] = e5

Parámetros de cliente_ping: destino, cantidad de pings, sondeos de espera por PONG, iteraciones de pausa. De coordinador: m y luego m parejas (nodo, n).

Parte II — Manual técnico

6. Interfaz común de las CPU

class CPU:                       # ANDES-64 (adaptador), Orinoco32, Caribe16
    FABRICANTE, MODELO, PALABRA
    cargar_fuente(ruta)          # ensambla con SU ensamblador y carga el binario
    paso() -> bool               # ejecuta UNA instrucción de su ISA
    detenida, instrucciones, salida
    enviar                       # función asignada por la red: recibe los bytes de la NIC
    rx                           # deque de paquetes entregados por la red

La red solo usa esa interfaz; agregar un cuarto fabricante consiste en escribir su clase y registrarla en arquitecturas.MODELOS, EXTENSION e IPC.

7. Flujo de un mensaje

  1. El programa ejecuta su instrucción de envío (NSEND / send / NSND). La CPU entrega los bytes a enviar → Red._desde_nic(nodo, datos).
  2. La red crea un Paquete('DATOS') con origen, destino (byte 0) y datos (bytes 1…), registra el envío y llama a _enviar_datos.
  3. Sin ruta: el paquete queda en nodo.pendientes y se inicia _descubrir (RREQ). Con ruta: _transmitir intenta hasta 3 veces; si tiene éxito, el paquete se agrega a en_vuelo con llegada en t + 1.
  4. En el tick siguiente, _recibir en el vecino reenvía o, si es el destino, agrega [origen] + datos a cpu.rx.
  5. El programa del destino lo lee con su instrucción de recepción.

8. Detalles de implementación

  • Determinismo: toda la aleatoriedad usa Red.rnd = random.Random(semilla); el orden de procesamiento de nodos y paquetes es fijo, por lo que una misma semilla produce exactamente la misma bitácora.
  • Tiempo: TICK_S = 0.01; el movimiento por tick es v·0,01 m.
  • Errores de CPU: si una CPU falla (opcode inválido, pila vacía…), el nodo se marca con error, deja de ejecutar y sigue funcionando como enrutador (la NIC y la capa de red no dependen de la CPU).
  • Parámetros (en red.py): REINTENTOS_MAC = 3, TTL = 12, VIDA_RUTA = 300, ESPERA_RREP = 40, MAX_RREQ = 3; relojes en arquitecturas.IPC.
  • Reutilización: andes64/ es una copia sin cambios del emulador de la Tarea 17; su NIC ya tenía el atributo enlace para conectarse a una red.
